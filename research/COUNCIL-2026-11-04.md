# The R&D council: what ten researchers found, and what Teslon should do

2026-11-04. Ten researchers and inventors were given the same brief: Teslon's
goal, how it works today, what it has measured, and where it fails. Each was
asked to dig past the well-known tools, into lesser-known GitHub repositories,
research artifacts and one-person projects, and to judge every finding against
Teslon's two rules:
- never silent;
- never a wrong skip.

This page puts their findings together, says where they agree, settles where
they disagree, and turns the result into a plan. It builds on
[RND-PLAN-2026-11-04.md](RND-PLAN-2026-11-04.md) and changes parts of it.

| Seat | Angle |
|---|---|
| R1 | Static extraction of service-to-service communication |
| R2 | Front end: routes, then API calls, then fields |
| R3 | Change impact analysis and regression test selection (research) |
| R4 | Fact sources compilers and builds already produce |
| R5 | Contracts, registries and several repositories |
| R6 | Runtime evidence: coverage and traces |
| R7 | Automatic truth: oracles and benchmarks |
| I1 | Inventor: run both versions and compare |
| I2 | Inventor: what would make Teslon 10x for a QA lead |
| I3 | Inventor: skips that are provably safe; framework knowledge as data |

## 1. Where all ten agree

These eight principles came up independently, from several seats each. They
are now Teslon's design rules.

1. **Verdicts form a lattice: SKIP < UNCLEAR < TEST.** Every source that is
   not a static proof can only raise a verdict, never create a SKIP. That
   covers runtime traces, coverage, git history, tickets, usage data, text
   search, and running both versions. "No diff seen" and "zero coverage"
   never prove anything. (I1, I2, I3, R3, R5, R6)
2. **A SKIP carries a proof object, and a separate checker re-checks it.** I3's
   certificate is a closed set of nodes that:
   - contains the area's entry points;
   - is closed under every edge rule;
   - shares nothing with what changed;
   - holds no unknown site.

   A small checker that shares no code with the engine recomputes it. If the
   check fails, the area is UNCLEAR. (I3, R4)
3. **Facts climb a ladder, and each fact records where it came from.**

   | Level | Source |
   |---|---|
   | L0 | Attested build artifacts: a SCIP index, OpenAPI and AsyncAPI files, build manifests, Spring configuration metadata, generated sources |
   | L1 | Compilers running inside Teslon's own process: the TypeScript checker, Vue language-core |
   | L2 | Pinned sidecars that need no build: JDT, go/packages, Roslyn |
   | L3 | Today's tokenizer and hand-written rules |

   A SKIP needs its whole path from L0 or L1 on both commits. An L3 path can
   give TEST or UNCLEAR, never a proven SKIP. (R4, with I3 and R1)
4. **An unknown is a fact, and Teslon counts them.** Wherever a reader gives
   up, it writes `Unknown(site, kind)` and never drops it. Three counts then
   become self-checks:
   - unknowns, ranked by how many areas each one turns UNCLEAR;
   - dangling edges: an outbound call or topic that matches nothing
     (spring-service-graph calls this CONTRACT_DRIFT);
   - files that change together with no static path between them.

   A new app announces its own blind spots before anyone trusts it. That is
   the answer to the 2-of-79 first run. (I3, R1, I2)
5. **A coarse, safe floor first; refine only where it can be proven.** Static
   selection at class or file level is about as safe as dynamic selection.
   Every miss in the main study came from reflection. A classifier of change
   kinds (FineRTS) is the main tool for "skip with proof". Dynamic sites
   become UNCLEAR, each with file:line, and are not over-approximated across
   the whole program. (R3)
6. **Join services on contract identity, never on name similarity.** Use:
   - fully qualified symbols;
   - generated contract types: a shared Feign interface, an
     openapi-generator client, Avro or Proto classes;
   - normalised keys: `http:{service}:{VERB}:{path}`, `kafka:{cluster}:{topic}`,
     `grpc:{pkg.Service}/{Method}`, `gql:{Type}.{field}`, package URLs.

   Every tool that links by name (Ariadne, MESA, MicroGraal) either breaks
   "never a wrong skip" or drowns in false links. (R1, R5, R2)
7. **Truth must come from outside Teslon's authors.** Hand truth written by
   the same mind as the rules shares its blind spots. Add:
   - automatic truth from mutations of runnable apps, checked by their E2E
     tests;
   - external ground-truth sets;
   - real PRs labelled by QA engineers;
   - RTSCheck-style rule checking.

   A gate passes only when every source passes it. (R7, R1, R3)
8. **Output is a pure function of its inputs, and private data never enters
   it.** The inputs are the base SHA, the head SHA and sorted evidence
   digests. Runtime files pass a fail-closed allowlist of attributes. Source
   text is stripped from coverage. Everything stays local. (R6, R4)

## 3. The inventors' ideas

**I1: run both versions.**
- *Boot-registry diff.* Start base and head with stubbed dependencies and no
  traffic. Dump what the framework resolved (routes, beans, listeners, jobs,
  effective config) and diff the two dumps.
- *Triple replay.* Send the same requests to base, a second copy of base, and
  head. The two base copies give the noise mask. Diff responses, database
  writes (CDC), Kafka records and outbound calls.
- *Seam transplant.* Render the base front end with the head back end's
  responses. Feed head's Kafka records to base's consumers. This executes
  Teslon's core story: "an API rename breaks page X".
- *Infection probes.* For each change, say whether it was not reached,
  reached with no effect, changed internal state but was masked, or reached
  the output.

Execution may block a SKIP. It may never create one.

**I2: what a QA lead needs beyond the code.**
- *Claim against reach.* What the PR and its ticket say, against what the
  code touches.
- *Co-change guard.* Git history can only veto a SKIP: "changed together in
  14 of 16 commits".
- *Rule-gap miner.* Strong co-change with no static path is a missing idiom,
  so it becomes the onboarding backlog. No prior art was found.
- *SZZ backtest.* Replay Teslon on past PRs. Any area where a later bug fix
  landed, and which Teslon would have skipped, was a wrong skip in history,
  and becomes an engine regression test.
- *Usage × criticality ordering.* Ranking only.
- *Feedback ledger.* QA marks noise in `.teslon/verdicts.yaml`, keyed to the
  evidence chain. A note expires when the code changes, and never becomes a
  SKIP.
- *Release ledger and test charters.*

**I3: sound by construction.**
- Framework knowledge goes into model packs: YAML rows in CodeQL's
  models-as-data style, with `entry`, `channel`, `summary` and `neutral`.
- Topics, routes and keys use a small string domain: a constant, a prefix, or
  any value (⊤).
- Each unknown site gets edges to every in-app method that fits its type
  ("havoc"), never to nothing.
- A model row from an LLM or a person is admitted only after it passes idiom
  probes, a recall check against runtime traces, and a noise gate.

The LLM proposes; the analyzer verifies.

## 4. Where they disagreed, and the decision

| Question | Positions | Decision |
|---|---|---|
| Can Spring AOT decide which bean a setting switches on? | My earlier note said yes. R4 found AOT freezes `@Conditional` to the build environment. | **No.** AOT output is read when present, never to decide `@ConditionalOnProperty`. Settings are resolved per profile from the YAML files (I3's string domain). |
| A Datalog core (Soufflé) or the existing Node graph? | I3: one Soufflé program. R4: SCIP into a Node reader. Packaging Soufflé for Node is unverified. | **Keep the Node graph. Add the certificate and checker first, with no rewrite.** Revisit Datalog once the certificate has proven itself. |
| Facts that need the app running (springdoc, Springwolf, actuator, FastAPI's OpenAPI) | They are exact, but they break "never start the app". | **Use them only as files CI already published.** Booting the app is an optional CI step, as in I1's boot-registry diff, never the core. |
| TypeScript 7 | npm's latest tag is now TS 7 (Go-native). Its programmatic API is "not ready". | **Pin the JS compiler API at 5.x or 6.x**, whatever version the project builds with. Spike TS 7 later. |
| Bytecode analysis (SootUp, WALA, OPAL, GraalVM points-to) | Precise call graphs, but annotations lose their line numbers and the toolchains are fragile (MicroGraal). | **Reject as a core.** Use scip-java (javac positions) and JDT. |
| Should an LLM decide anything? | Several tools are LLM-based. ESEM 2026 (unverified) reports GPT-4o F1 of about 0.60 on service links. | **An LLM only proposes**: a model row, a claimed area. Probes and the checker admit it. It never decides a verdict. |
| Is mutation-based truth enough? | Just et al.: 17% of real faults couple to no mutant. Dynamic impact analysis reached only 47–52% precision against execution-diff truth. | **No single source is enough.** Use automatic truth, hand truth and real-PR truth together. Each probe carries its source. "Reached but nothing observed" is UNKNOWN, never QUIET. |

## 5. The plan, revised

Each phase ends with the same gates:
- 0 silent;
- 0 wrong skips;
- 0 citation failures;
- 0 crashes;
- extra ≤ 5%;
- held ≤ 10%.

The gates are measured on hand truth, automatic truth and external truth.

**Phase A: honesty first. 2–3 weeks, no rewrite.**
1. **Unknown ledger, skip certificates, an independent checker, and the
   dangling-edge rate** (I3, R1).
   - Every place a rule or the tokenizer gives up writes an Unknown.
   - Every SKIP gets a certificate.
   - The checker is about 300 lines, kept apart from the engine.
   - Measure on the 266 probes plus the 79-probe first run. Hypothesis: at
     least 90% of the past wrong answers would have been UNCLEAR.
2. **Co-change guard and rule-gap miner** (I2). One pass over git history:
   offline, deterministic, and only ever adding UNCLEARs.
3. **Claim against reach** (I2): match IDs and names between the PR and ticket
   text and Teslon's area catalog.
4. **Automatic truth, version 0** (R7). This needs:
   - RealWorld's Playwright suite as the oracle;
   - Teslon-specific mutators, frozen in advance and placed by sampling real
     commit history;
   - the labels MUST, SHOULD, QUIET and UNKNOWN;
   - microSecEnD and the EMSE 2025 sets as truth Teslon did not write.

**Phase B: facts from the toolchain.**
1. **Java: a SCIP reader in Node, and scip-java.** scip-java now covers
   Kotlin too, since scip-kotlin was merged into it. Index base once from
   main and head on each PR.
   - Fully qualified symbols end the class-name collisions between services.
   - javac resolves receivers, chained getters and lambda parameters.
   - Generated sources are indexed as code: MapStruct `*MapperImpl` and
     `spring-aot`. So is `spring-configuration-metadata.json`.
   - The no-build fallback is a JDT sidecar that also emits SCIP.
2. **TypeScript: the checker everywhere.** R2's experiment found `findReferences`
   on a typed API client gives exactly the components that read a field. It
   works through generics, `Pick<>`, destructuring and nesting.
   - Add `@vue/language-core` so Vue templates join the same program.
   - Route inventories come from what each framework generates: Next.js
     adapters or `next typegen`, `react-router routes --json`, TanStack's
     `routeTree.gen.ts`, Vue Router 5's route map, and the Vite manifest's
     `dynamicImports`. File conventions are the fallback.
3. **Contract-identity joins** (principle 6) and FineRTS-style change kinds.

**Phase C: several repositories, and runtime evidence.**
1. **Per-repository fact files and a `workspace.json`**, which lists:
   - the deployed commit for each environment;
   - per key namespace, whether the consumer set is `complete`.

   Declared consumers come from:
   - Kafka ACLs and GitOps files;
   - CycloneDX SBOMs, for library version skew;
   - consumer mocks (WireMock, MSW, Pact), for field-level use;
   - persisted GraphQL documents.

   Version skew is reasoned with GraphQL Hive's model: consumer, version,
   environment, operations. A key with no consumer is SKIP only when its
   namespace is declared complete. Otherwise the answer is "no consumer found
   in N repositories (open world)", which is UNCLEAR.
2. **A runtime evidence layer**, read from files only. Inputs:
   - monocart per-test coverage, plus a log of the pages each test visited;
   - JaCoCo per session, or Teamscale Testwise;
   - raw OpenTelemetry spans, filtered by an allowlist.

   It follows a published evidence manifest and a `test.id` convention, and
   the verdict is the higher of the static and runtime ones.

**Phase D: execution, as an optional CI step.**
1. **Boot-registry diff** (I1-A).
2. **I1's bet**, a two-week experiment on ShopFlow's 79 probe PRs: seam
   transplant at the HTTP seam, triple replay, and infection probes.
   - **Success:** at least 25% of UNCLEAR areas turned into TEST with proof;
     noise under 5%; under 15 minutes per PR; zero SKIPs created by
     execution.
   - **Stop:** noise above 10%, or more than 30% of boots failing.

**Phase E: more languages, behind the same ladder.** Kotlin through scip-java,
then Python through scip-python, .NET through scip-dotnet, and Go through
go/callgraph or scip-go.

## 6. What this changes in Teslon's promise

- **"Never a wrong skip" becomes checkable.** Each SKIP carries a certificate.
  The checker that verifies it is independent of the engine. The
  assumptions it rests on are printed beside it: the active profiles,
  library code calling back only through overrides, AOP only through
  modelled pointcuts.
- **A new app shows its blind spots instead of hiding them.** Unknowns,
  dangling edges and coupling the graph cannot explain are counted and
  shown. The 2-of-79 kind of failure turns into UNCLEAR with named gaps.
- **Rules stop being the user's problem.** Facts come from compilers and
  build artifacts. What is left of framework knowledge lives in admitted
  model packs, each tested. The gap list comes from the app's own history.
- **Noise is bounded for each rule.** The feedback ledger, the noise gate on
  each model row, and the not-useful rate per rule stop a noisy rule before
  QA stops reading.

## 7. Limits of this research

Many hosts could not be reached from this session: arxiv.org, nextjs.org,
playwright.dev, opentelemetry.io, docs.teamscale.com, the-guild.dev,
docs.github.com, and others. Findings that rest on them come from search
snippets and are marked unverified in each seat's notes. Star counts and
dates were read from GitHub pages or git clones on 2026-11-04.

- the full text of the AWS paper on checking taint models;
- the ESEM 2026 LLM study;
