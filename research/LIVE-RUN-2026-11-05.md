# Live run: Teslon on real GitHub pull requests

2026-11-05. Task 6, the first run of Teslon end to end on GitHub. That means
real repositories, real pull requests, the Teslon GitHub Action on GitHub's
runners, and the PR comment it posts. Nothing in it was simulated.

## What ran

| Repository | Pull requests | What they are |
|---|---|---|
| [abhijeet1771/orderdesk](https://github.com/abhijeet1771/orderdesk) | 29 (#1–#29) | Every proving-ground scenario that is a single PR (`bench/proving-ground/scenarios.mjs`). They were published with `bench/proving-ground/publish.mjs`. |
| [abhijeet1771/shopflow](https://github.com/abhijeet1771/shopflow) | 26 (#1–#26) | 26 of the 79 ShopFlow probes, across all five groups: Kafka 7, mappers 5, Vue 7, services 5, `@Async` 2. They were published with the new `bench/probes/publish.mjs`. |

- Each PR body states the truth written before Teslon ran.
- The workflow is the one in `fixtures/orderdesk/.github/workflows/teslon.yml`.
  It uses `abhijeet1771/Teslon@claude/beautiful-galileo-9ay5n1`, so the Action
  builds this branch on the runner.

## The result

**55 of 55 PR comments give exactly the answer of the local run on the same
commits.** The local run is the one the probe and proving-ground truth were
checked against. Live and local agree on:
- the Test, Safe to skip and Unclear counts;
- the confidence;
- the skips the checker refused.

- **Runs:** 56 Teslon runs on GitHub, all green. That is 30 on OrderDesk (one
  re-run by hand) and 26 on ShopFlow.
- **Citations:** every cited line re-checked against GitHub's test-merge
  commit. That is 12 to 184 citations per PR, with no failures.
- **The checker shows up live.**
  - Every comment with a skip says "each with proof, re-checked by an
    independent checker".
  - ShopFlow #5 (the payments topic constant renamed) says "1 skip it could
    not prove is held as unclear". That is the k13 refusal measured in
    [CERTIFICATE-2026-11-05.md](CERTIFICATE-2026-11-05.md).
- **Changes with no app effect:**
  - docs-only, CI-only and test-only PRs (OrderDesk #8, #9, #23) got "Nothing
    to test in the app";
  - a changed image no code names (#29) held every screen as unclear, and said
    why.
- **Hostile text** (OrderDesk #22: `@everyone`, a `javascript:` link and an
  `<img onerror>` in a heading) came out escaped in the comment.
- **The PR range.** Every comment reads "checked as if merged into main
  today", with GitHub's test-merge commit.

## What went wrong, and whose it was

| What | Whose | What was done |
|---|---|---|
| GitHub returned 500 and 502 on PR creation and on one workflow dispatch, for about 10 minutes. Some PRs were created despite the error. | GitHub | Waited it out, listed the PRs before each retry, and created them one at a time. No duplicates. |
| On ShopFlow, opening a PR started no workflow run. The workflow was active, and OrderDesk's PRs did start runs. | GitHub (the cause is not known; the repository was pushed during the 5xx window) | Ran the same workflow with `workflow_dispatch` and the PR number, which it accepts. The comment and the result are the same as for a PR event (ShopFlow #1 was checked both ways). |
| The run artifacts (report.json, the cockpit) could not be downloaded from this session. Their storage host is not on the session's network allowlist. | This session's network | The PR comments were read through the GitHub API instead. The artifacts are on GitHub for 30 days. |

None of these was a Teslon failure.

## What this proves, and what it does not

- **It proves the whole path works.** That is the Action on a GitHub runner,
  the PR range from GitHub's test merge, citations re-checked there, and the
  comment posted and kept to one per PR. It gives the same answer as the lab
  runs that the truth was checked against.
- **It does not prove the truth on real teams' code.** These are Teslon's own
  fixtures, and their truth was written by the same project. The next step is
  the pilot from the launch plan: the last 50–100 merged PRs of a real team,
  checked against what their QA actually found.
